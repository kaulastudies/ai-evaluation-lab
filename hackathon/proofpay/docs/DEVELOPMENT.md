## Runtime and installation

Use Node.js 24.x and the committed lockfile. Current direct runtime versions include Next.js 16.4.5, React/React DOM 19.2.8, `pg` 8.23.1 and `@vercel/oidc` 4.0.7. The [dependency review](../evidence/dependency-remediation-2026-11-08-summary.json) records exact versions and the zero-finding audit.

```sh
git clone --branch proofpay/purchase-desk-v0.1 https://github.com/kaulastudies/ai-evaluation-lab.git
cd ai-evaluation-lab/hackathon/proofpay
npm run install:ci
```

`install:ci` runs `npm ci` with development and optional dependencies. Do not run an installer while another process is building/testing the same checkout. Never commit environment values, database connections, owner keys, session cookies or generated output.

## Server configuration

Use uncommitted `.env.local` for development and the selected Vercel environment for deployment. Next.js loads local environment files; the standalone migration script needs exported variables or Node's explicit `--env-file` option. A local file does not configure Vercel. Do not prefix these variables with `NEXT_PUBLIC_`.

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Authenticated remote PostgreSQL runtime connection; use the provider's pooled URL. `POSTGRES_URL` is a fallback name. |
| `DATABASE_URL_UNPOOLED` | Preferred dedicated direct connection for migrations and live database checks. Migration fallback order is `POSTGRES_URL_NON_POOLING`, `DATABASE_URL`, then `POSTGRES_URL`. |
| `OWNER_ID` | Stable owner identifier: 1–128 letters, digits, underscores or dashes. |
| `OWNER_PASSWORD_HASH` | Salted scrypt hash of the dedicated owner key, generated by the script below. Never the plaintext key. |
| `SESSION_SECRET` | Independently generated cryptographic secret, 43–128 base64url characters, used to sign sessions. |
| `APP_ORIGIN` | Exact canonical HTTPS origin, without a path/query/fragment; for local HTTPS use `https://localhost:3000`. |
| `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_MERCHANT_ID` | Sandbox application credentials and expected test merchant. Needed for sandbox paths, not rehearsal. |

A dedicated owner key must be 16–256 characters. `scripts/hash-owner-key.mjs` reads it from stdin and prints only its salted hash:

```sh
node scripts/hash-owner-key.mjs
```

Supply the key through a private stdin/password-manager workflow and end input; do not put it in command arguments, history, source, screenshots or this guide. Store the plaintext key privately for sign-in and the hash in server configuration. Generate `SESSION_SECRET` separately; rotating it invalidates existing signed sessions. Changing `OWNER_ID` also changes the owner namespace, so do not use it as a routine password-reset mechanism.

## PostgreSQL migrations and tests

The application requires remote authenticated PostgreSQL with certificate-verified TLS. It fails closed when configuration is missing; there is no SQLite, browser-storage or local-file ledger fallback. Tests may still use controlled SQLite fixtures for the shared service contract; that does not make SQLite the production database.

Review `db/postgres/*.sql`, then apply them to the dedicated database:

```sh
node --env-file=.env.local scripts/migrate-postgres.mjs
```

If variables are already exported, `npm run db:migrate` invokes the same script. It uses a transaction and advisory lock, records filenames/checksums in `proofpay_migrations`, skips matching applied migrations and rejects changed checksums. Add a new migration instead of editing one already applied. The old `drizzle/` SQLite migrations remain test/historical inputs; do not run them against PostgreSQL. Provisioning or connecting a Neon database does not prove its schema has been applied.

The explicit real-database gate is:

```sh
node --env-file=.env.local --test tests/review-postgres-live.mjs
```

It creates a fresh random `proofpay_test_*` schema, applies the PostgreSQL migrations there, exercises concurrent reservations, rollback, capture/recovery and funding claims, then drops that schema. Use a dedicated authorized test connection, preferably unpooled. Missing configuration fails the gate rather than skipping it. The test makes no PayPal/model calls. It does not prove every distributed database failure mode.

CI's disposable PostgreSQL service uses `PROOFPAY_TEST_ALLOW_LOCAL_DB=1` only with a loopback address to permit non-TLS local testing. This exception belongs to the test script; it is not a production runtime setting. Remote Neon uses verified TLS.

## Interactive development and owner sessions

After database and owner setup:

```sh
npm run dev -- --experimental-https
```

With `APP_ORIGIN=https://localhost:3000`, use that exact HTTPS origin and the dedicated owner key. Next's [HTTPS development option](https://nextjs.org/docs/app/api-reference/cli/next#using-https-during-development) generates a local certificate; trust the local development certificate appropriately. Do not disable TLS validation for remote services. `npm start` serves a production build; it does not deploy or migrate the database.

`POST /api/auth/login` takes `{ "password": "..." }`, verifies the scrypt hash and issues an eight-hour `__Host-proofpay-session` cookie: Secure, HttpOnly, SameSite=Strict, host-only, `Path=/`. Mutations require the exact configured `Origin` and JSON. Sites/Vercel identity headers never authorize the owner. There is no mock login.

A durable global counter admits at most ten login attempts per minute across instances; HTTP 429 includes `Retry-After: 60`. `POST /api/auth/logout` with `{}` clears this client's cookie. It does not revoke a copied token; expiry or session-secret rotation handles that boundary. Missing owner/database configuration returns a bounded error instead of exposing a workspace.

## Rehearsal and PayPal diagnostic

In **Connections**, start the $300 rehearsal. Approve a sample request, create its simulated order, select **Drop the capture response**, capture, reload and check the original simulated outcome. No external model or PayPal call is made, but state is stored in PostgreSQL.

**Test PayPal sandbox** calls `POST /api/sandbox/diagnostic/start` with `{}`. It creates one unapproved, fixed $180 USD `workflow-review` request with `sandbox-diagnostic`, `manual: true` and `aiCalled: false`. Creation makes no provider call. Additional proposals are rejected in that profile, even if AI is configured.

The diagnostic uses the shared owner approval, reservation, expiry, native buyer approval, dispatch and reconciliation controls. Use a separate PayPal sandbox buyer; an API secret or return URL is not buyer consent or confirmation. A reserved/uncertain active sandbox blocks workspace switching. Do not retry an uncertain capture or erase its reservation. The earlier verified diagnostic belongs to the former runtime; current Vercel execution needs its own evidence.

## Bounded runtime AI

The selected path is Vercel AI Gateway using request-context OIDC, fixed `openai/gpt-4.1-mini` and a reviewed free-credit allowance. The SDK obtains the current identity token on Vercel; do not paste or commit `VERCEL_OIDC_TOKEN`. Local token strings and public headers are not promoted into platform credentials.

| Variable | Required value or rule |
|---|---|
| `AI_FUNDING_MODE` | `vercel-free-credit` |
| `AI_GATEWAY_FREE_ONLY_CONFIRMED` | `true` only after checking the account's free credit, disabled auto-top-up and absence of BYOK/paid fallback. |
| `AI_GATEWAY_GRANT_ID` | Stable reviewed grant reference, 1–80 letters/digits/underscores/dashes. |
| `AI_GATEWAY_GRANT_EXPIRES_AT` | Explicit future UTC ISO timestamp; use a short reviewed window, not a perpetual placeholder. |
| `AI_GATEWAY_MAX_REQUESTS` | Current selected cap: `1`. Validation permits 1–10. |
| `AI_GATEWAY_MODEL` | `openai/gpt-4.1-mini` |

Leave `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL` and `AI_GATEWAY_API_KEY` unset; populated legacy variables are rejected. **Do not use personal OpenAI credits.** The model name identifies the gateway's model, not a personal billing account. [RESOURCE_PLAN.md](RESOURCE_PLAN.md) records the observed $4.93 free balance and confirmed model eligibility and remaining execution checks.

Before inference, one attempt and its event are durably claimed. There is one dispatched attempt per workspace and a grant-wide total across workspaces. Failed, timed-out and invalid responses consume the attempt; no automatic retry, refund or alternate provider exists. Repeating a successful identical idempotency key reads the existing proposal. Do not delete attempt rows, replace grant IDs or create new grants to bypass the limit.

The adapter caps input at 2,000 characters and output at 400 tokens, requests a strict SKU/rationale schema and validates the permitted item. The server owns price, merchant, currency, allowance and approval. Grant configuration is an operator declaration, not a live billing attestation. Recheck balance/eligibility and retain actual response/usage evidence before claiming runtime AI works.

## API and developer tools

| Method | Path | Action |
|---|---|---|
| POST | `/api/auth/login` | Owner key → signed session. |
| POST | `/api/auth/logout` | Clear this client's cookie; body `{}`. |
| GET | `/api/state` | Owner's active workspace, operations and events. |
| POST | `/api/rehearsal/start` | Seed an isolated simulated workspace. |
| POST | `/api/sandbox/diagnostic/start` | Fixed manual/no-AI sandbox request; body `{}`. |
| POST | `/api/workspaces` | Start a workspace with explicit `mode`. |
| POST | `/api/proposals` | `request`, `mode`, `idempotencyKey`; server-controlled selection policy. |
| POST | `/api/operations/:id/approve`, `/cancel`, `/renew-approval`, `/create-order` | Exact operation and current positive `approvalVersion`. |
| POST | `/api/operations/:id/capture` | Current approval version; optional `fault: "drop-response"`. |
| POST | `/api/operations/:id/reconcile` | Read the original provider order; body `{}`. |
| GET | `/api/operations/:id/evidence` | Export that owner's versioned operation receipt. |

The [Postman guide](../postman/README.md) supplies a credential-free collection for session/workspace/approval/evidence inspection. Its offline schema/script checks are not actual Postman execution. Use individual requests and the HTTPS cookie jar.

For an exported version 1 receipt:

```sh
node scripts/verify-receipt.mjs /path/to/receipt.json
```

The command accepts a regular JSON file up to 1 MiB, checks the approval binding and internal record consistency, prints JSON on success and exits 1 on invalid input. It makes no network call. Manual diagnostic output remains explicitly no-AI. The digest does not cover all prose, and an author can replace both data and digest; authenticity, current authority, model execution and TIP compatibility are outside its claim.

Source map: `app/api` handles routes; `auth.ts`/`login.ts` own sessions; `service.ts` owns financial transitions; `ai-funding.ts`/`ai.ts` own bounded proposals; `provider.ts` owns PayPal/rehearsal transport; `postgres-database.ts` and `db/postgres/` own current persistence. The responsive fixture renders real components with synthetic records; inspect it in a browser after styling changes.

## Vercel build gate

The checked-in `vercel.json` runs the isolated real-PostgreSQL suite before the checksum-locked schema migration and native Next.js build. A failing test stops schema application and release. The install/build commands remove Vercel's unsupported npm `cache-dir` environment alias; npm's normal warning and audit reporting stay enabled. Dependency install scripts are approved only for reviewed, exact package versions.
